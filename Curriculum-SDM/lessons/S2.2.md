# S2.2 — How the menu is built (management tasks)

## In one line
SDM builds **each person's menu from their AAD groups**: groups map to "management tasks," and a link shows up only if the user holds the task that grants it.

## The idea
This is the mechanism behind the per-user menus from S1.3. When the menu is requested, `NavigationLinkService` does three things:

1. **Reads the user's `DA-*` AAD groups** (from the sign-in claims / a directory lookup).
2. **Maps those groups to "management tasks"** via a SQL stored procedure — each task is a string like `"Schools"` or `"Standalone Groups"`.
3. **Emits only the links the user is entitled to** — every navigation link has a rule whose label matches a management task, and the link is included **only if** the user's tasks contain that label.

So the menu is assembled per request, per user. Two people with different `DA-*` groups get different management tasks and therefore **different menus** — exactly why a `403` (S1.3) and "I can't see that screen" are the same underlying cause: the group isn't there, so the task isn't there, so the link isn't there.

There's one deliberate exception: the **Training** menu is appended **unconditionally** from configuration (it isn't gated by a management task), so every authenticated user sees it.

(What a menu item *does* is a separate question from how it's listed — e.g. the **Standalone Group** item is also where the Help Desk grants temporary access via Entra group memberships; see S1.4.)

## Why it matters
When someone says "the menu is missing an item," this is the chain to walk: group → task → link. The fix is almost never in SDM's code — it's the user's **AAD group membership** (maintained upstream by Sync-DDH-AAD), which then yields the management task that surfaces the link.

## Watch out for
**"The menu is a fixed list in the app."** It's computed per user. The static part is the *catalog* of possible links; which ones you actually see depends on your groups → tasks.

## You've got this when you can…
- Walk the chain: `DA-*` groups → (SQL) management tasks → the links whose task the user holds.
- Explain why two users see different menus, and why a missing item usually means a missing **group**, not a bug.
- Name the exception (Training is always shown, config-driven, not task-gated).
