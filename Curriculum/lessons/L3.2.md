# L3.2 — Read a run in StarBridge

## In one line
When the console isn't enough, **StarBridge has the receipts**: every record's outcome, every field change, and every error are queryable tables.

## The idea
StarBridge (L1.5) records what each run did. Three places to look:

- **`EntityTransaction`** — one row per processed record, with an **`Outcome`** column stored as an **integer 1–11** (exactly L1.10's outcomes):

  ```sql
  SELECT TOP 1000 [Id], [TimeStamp], [Outcome], [EntityTypeId], [SourceSystemEntityId]
  FROM [Console].[EntityTransaction]
  WHERE Outcome = 11           -- 11 = ExceptionThrown; 9 = ReferredForManualDeduplication; 2 = Rejected
  ORDER BY [TimeStamp] DESC;
  ```

  | # | Outcome | | # | Outcome |
  |---|---|---|---|---|
  | 1 | Skipped | | 7 | DuplicateDetectedChangesMerged |
  | 2 | Rejected | | 8 | DuplicateDetectedNoChangesMerged |
  | 3 | NoChangesDetected | | 9 | ReferredForManualDeduplication |
  | 4 | NoChangesMerged | | 10 | NewEntityCreated |
  | 5 | ChangesDetectedAndMerged | | 11 | ExceptionThrown |
  | 6 | NotFoundInDestinationSystem | | | |

- **`EntityValueChange`** — the **field-level diffs**: which property changed from what to what.
- **`Operation` / `Message`** — the **text** of rejections, warnings, and exceptions tied to an operation.

## Why it matters
The console scrolls away and only shows tallies. StarBridge lets you answer the precise questions: *which* records threw, *what* field changed on a specific entity, *why* something was rejected.

## Watch out for
- **Forgetting the Outcome codes are integers** — filter `Outcome = 11`, not `= 'ExceptionThrown'`.
- **Looking only at EntityTransaction for errors** — the *message text* lives in Operation/Message (L3.3).

## You've got this when you can…
- Name the three things StarBridge records (per-record outcomes, field diffs, error text) and their tables.
- Write/read a query that finds the records with a given Outcome (e.g. all ExceptionThrown).
