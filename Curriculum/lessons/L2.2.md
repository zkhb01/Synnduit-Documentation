# L2.2 — Implement a Feed

## In one line
A **feed** is the **source connector**: `class XFeed : IFeed<X>` whose `LoadEntities()` reads the source and returns a **full snapshot** of POCOs — the engine does the diffing.

## The idea
You implement the generic interface `IFeed<X>`, binding `<X>` to your entity (L0.G2). The **contract is always the same** — `LoadEntities()` returns a full, materialized snapshot of POCOs — but *how* you read the source depends on what the source is.

**Example — an EF/SQL source** (`StaffFeed`, reading the HRAD database):

```csharp
[Feed(SourceSystem = typeof(HumanResources))]
public class StaffFeed : IFeed<Staff>
{
    private readonly HradFactory hradFactory;
    public StaffFeed(HradFactory hradFactory) => this.hradFactory = hradFactory;   // injected (L0.D1)

    public IEntityCollection<Staff> LoadEntities()
    {
        using var context = this.hradFactory.CreateHRAD();
        return context.CCS_HR_AD_SYNC
            .Where(Util.ActiveStaffWithManager)
            .Select(s => new Staff { EmployeeId = s.EMPLID, FirstName = s.FIRST_NAME, /* ... */ })
            .ToList();                                  // materialize before the context is disposed
    }
}
```

Three things to get right:
1. **`[Feed(SourceSystem = typeof(...))]`** marks the class so the engine discovers it (more in L2.5).
2. **`IFeed<Staff>`** — the `<Staff>` is your entity type.
3. **`LoadEntities()`** reads the source, **projects** into POCOs, and returns a **materialized** snapshot. Here the source is an EF `DbContext`, so you `.ToList()` **while the context is open** — a lazy `IQueryable` returned to the engine would blow up after the `using` disposes.

> **Recommended (EF sources only):** if your source is a SQL database queried with Entity Framework, review **L0.E1** (querying with EF, deferred execution) — it's what makes the `.ToList()` step click. It isn't a prerequisite for writing a feed in general; an API or file feed doesn't touch EF at all.

**The source isn't always a SQL database.** The exact same interface backs any source; you just fill `LoadEntities()` with whatever reads it — and the EF-specific `.ToList()`/`DbContext` concerns simply don't arise when there's no `DbContext`:

```csharp
// An API/provider source (PowerSchool) — call the service, project, return. No DbContext, no .ToList() gotcha.
[Feed(SourceSystem = typeof(PowerSchool))]
public class CalendarCategoryFeed : IFeed<CalendarCategory>
{
    [ImportingConstructor]
    public CalendarCategoryFeed(ICalendarCategoryProvider provider) => this.provider = provider;

    public IEntityCollection<CalendarCategory> LoadEntities() =>
        this.provider.GetCalendarCategories()
            .Select(c => new CalendarCategory { Code = c.Code, Desc = c.Desc })
            .ToEntityCollection();
}
```

A **JSON file** feed reads and deserializes into POCOs (`JsonFeed<T>`); a **ServiceNow** or other API feed calls its service. Same contract every time.

What's **invariant** across all of them: return the *whole* snapshot of POCOs, materialized — you do **not** compute the delta; the engine diffs your snapshot against last run's recorded state.

## Why it matters
The feed is half of every integration, and it's the same contract whatever the source — SQL, an API, a file. The **projection into POCOs** and **returning a full, materialized snapshot** are the constants people get wrong. (For EF-backed sources there's the extra `.ToList()` step; for API/file sources the data is already concrete.)

## Watch out for
- **Doing the delta yourself** — don't filter to "only changed rows"; return everything and let the engine diff. *(applies to every source)*
- **(EF/SQL sources only) Returning an un-materialized `IQueryable`** — it executes after the `using` disposes the `DbContext` → crash. `.ToList()` while the context is open. An API/file feed already holds concrete data, so this doesn't apply.
- **(EF/SQL sources only) Complex C# inside the LINQ query** — EF can't translate it; materialize first, then transform in memory.

## You've got this when you can…
- Write `[Feed(SourceSystem = typeof(...))] class XFeed : IFeed<X>` with a `LoadEntities()`, for a SQL, API, or file source.
- Explain that `LoadEntities()` returns a full materialized snapshot of POCOs, and that the `.ToList()`/disposed-context concern is specific to EF-backed sources — not a universal feed rule.
