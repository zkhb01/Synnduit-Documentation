# L2.3 — Implement a Sink

## In one line
A **sink** is the **destination connector**: `class XSink : ISink<X>` implementing **New / Create / Get / Update / Delete**, with the destination service handed in through its **constructor**.

## The idea
`ISink<X>` is the contract the engine drives to apply the delta. You implement all five members:

```csharp
[Sink(DestinationSystem = typeof(SchoolObjectModel))]
public class TeamSiteWebPartSink : ISink<TeamSiteWebPart>
{
    private readonly ITeamSiteWebPartService service;

    [ImportingConstructor]                                     // injected, not new-ed (L0.D1 / L2.5)
    public TeamSiteWebPartSink(ITeamSiteWebPartService service) => this.service = service;

    public TeamSiteWebPart New() => new TeamSiteWebPart();     // a blank instance to populate
    public void Create(TeamSiteWebPart e) => this.service.Create(e);
    public TeamSiteWebPart Get(TeamSiteWebPart e) => this.service.Get(e.Id);
    public void Update(TeamSiteWebPart e) => this.service.Update(e);
    public void Delete(TeamSiteWebPart e) => this.service.Delete(e.Id);
}
```

The five members, in plain terms:
- **`New`** — hand back a fresh, empty entity for the engine to fill.
- **`Create`** — write a brand-new record to the destination.
- **`Get`** — fetch the current destination record.
- **`Update`** — apply changes to an existing record.
- **`Delete`** — remove a record (used by garbage collection).

The class **receives `ITeamSiteWebPartService` via its constructor** — it never `new`s it. Something else (MEF, L2.5) supplies it.

## Why it matters
The sink is the other half of every integration. Because you program to `ISink<T>`, the engine can drive any sink you write without knowing your concrete class — that's the whole plug-in model.

## Watch out for
- **Implementing only some members** — `ISink<T>` is a contract; all five must be present or it won't compile.
- **`new`-ing the service** inside the sink — take it via the constructor instead, so it can be supplied and swapped.
- **Putting source-reading logic here** — reading is the feed's job; the sink only writes the destination.

## You've got this when you can…
- Write `[Sink(DestinationSystem = typeof(...))] class XSink : ISink<X>` with all five members.
- Say which member each delta action maps to, and how the sink obtains its service.
