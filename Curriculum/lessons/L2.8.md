# L2.8 — Configuring garbage collection & orphan-mapping behavior

## In one line
Two annotation knobs control cleanup: **`GarbageCollectionBehavior`** — *which* unreferenced destination records GC deletes — and **`OrphanMappingBehavior`** — what happens to a *mapping* whose source record has disappeared.

## The idea
Cleanup (L1.7's GarbageCollection segments, and the orphan handling in L1.12) isn't one-size-fits-all — you tune it per entity or per system with attribute parameters. They're two **separate** levers acting on different things: GC behavior deletes destination **entities**; orphan behavior disposes of **mappings**.

### `GarbageCollectionBehavior` — how much GC deletes
Set on `[EntityType]` (one entity) or `[ExternalSystem]` (a whole destination system). It bounds which *unreferenced* destination entities garbage collection will remove:

| Value | Deletes… | Safety |
|---|---|---|
| `DeleteCreated` *(default)* | only unreferenced entities **this system instance created** | safest — you only clean up what you made |
| `DeleteMapped` | unreferenced entities that have **at least one mapping** (from creation *or* dedup) | broader |
| `DeleteAll` | **every** unreferenced entity, even ones with no mapping / not created by this sync | most aggressive |

```csharp
[EntityType(
    "2B03A49B-0490-429A-9BC4-350DE2E8EB46", typeof(SharePointOnLine),
    Name = "SharePoint.TeamSiteAssetPrincipalPermission",
    GarbageCollectionBehavior = GarbageCollectionBehavior.DeleteAll)]   // authoritative for the whole set
public class TeamSiteAssetPrincipalPermission : Entity { ... }
```

Use `DeleteAll` only when the sync is the **authoritative owner** of the entire set (so anything not in the source genuinely shouldn't be there). `DeleteCreated` is the conservative default.

### `OrphanMappingBehavior` — what happens to a stranded mapping
Set on `[SourceSystemParameters]` (or `[Feed]`/`[EntityType]`/`[ExternalSystem]`). When a mapping's source entity is no longer in the snapshot (L1.12), this decides the mapping's fate:

| Value | Effect |
|---|---|
| `None` *(default)* | do nothing — the mapping stays **active** |
| `Deactivate` | the mapping is **deactivated** (kept, can be reactivated) |
| `Remove` | the mapping is **removed** entirely |

```csharp
[ExternalSystem(
    "DA958D35-0EE8-4B25-91EE-B0990B021098", Name = "School Object Model",
    GarbageCollectionBehavior = GarbageCollectionBehavior.DeleteMapped)]   // system-wide default
[SourceSystemParameters(OrphanMappingBehavior = OrphanMappingBehavior.Remove)]
public class SchoolObjectModel { }
```

This ties back to what you already know:
- **`None`** means *no orphan processing happens*, so the **orphan-mapping abort threshold (L1.12) has nothing to act on** — cleanup falls entirely to `GarbageCollectionBehavior`.
- **`Deactivate`/`Remove`** are what produce the "orphan mappings identified for deactivation/removal" the threshold guards. **`Remove`** is also what puts a recovered record on the *dedup* path after a fixed feed re-run (L3.4): with its mapping gone, it re-matches by `[DuplicationKey]` (`DuplicateDetectedNoChangesMerged`) instead of matching straight through.

### Levels & precedence
Both behaviors can be set at more than one level (entity type, external system, source system). A **more specific setting wins** — so a system-wide `[ExternalSystem]` default applies to all its entities, and any single `[EntityType]` can override it. In the examples above, `SchoolObjectModel` is `DeleteMapped` system-wide, while `TeamSiteAssetPrincipalPermission` opts *itself* up to `DeleteAll`.

## Why it matters
The defaults (`DeleteCreated`, `None`) are deliberately cautious — out of the box, a sync barely cleans up after itself. You **opt into** more aggressive cleanup entity by entity, matching the behavior to how authoritative the sync is for that data. Getting this wrong in the aggressive direction deletes data you didn't own; in the timid direction it lets stale records accumulate.

## Watch out for
- **Don't confuse the two knobs.** `GarbageCollectionBehavior` deletes destination **entities**; `OrphanMappingBehavior` disposes of **mappings**. `None` and `DeleteCreated`/etc. are not interchangeable — they're different enums for different jobs.
- **`DeleteAll` is a loaded gun.** It removes unreferenced records this sync never created — only use it where the sync owns the full set.
- **Leaving `OrphanMappingBehavior` at `None` disables the orphan-mapping threshold's protection** for that entity (there are no orphan candidates to count); the GC threshold/behavior is your only guard then.
