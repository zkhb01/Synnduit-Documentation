# L2.1 — Write a POCO

## In one line
A POCO is a plain C# class that describes **one entity type**, and its **attributes are the contract** that tells the engine how to handle it — with **every property nullable**.

## The idea
This is the first thing you write for a new integration. From `Staff.cs`:

```csharp
[EntityType("2853506F-8A34-4296-A71A-E175A0EC6EA6", typeof(SchoolObjectModel))]
public class Staff : Entity
{
    [SourceSystemIdentifier]
    public string? Code { get; set; }            // the ID in the source

    [EntityProperty]
    [DuplicationKey]                              // the natural business key we dedupe on
    public string? EmployeeId { get; set; }

    [EntityProperty] public string? FirstName { get; set; }
    [EntityProperty] public string? LastName  { get; set; }
}
```

Each attribute does one job:

| Attribute | Job |
|---|---|
| `[EntityType(<guid>, <destinationSystem>)]` | globally identifies the entity |
| `[SourceSystemIdentifier]` / `[DestinationSystemIdentifier]` | which property holds the source-side / destination-side ID (the two ends of a mapping) |
| `[EntityProperty]` | this field is tracked for change detection |
| `[DuplicationKey]` | the natural business key used to match possible duplicates |

**Every property is nullable** (`string?`, `int?`, `DateTime?`). This is a hard Synnduit requirement (L0.E2): a non-nullable property breaks change detection and loading in subtle ways.

## Why it matters
The POCO is the shared vocabulary your feed and sink both speak. Get the attributes wrong and the engine silently mis-tracks, mis-maps, or fails to dedupe — none of which is a compile error.

## Watch out for
- **Forgetting `[EntityProperty]`** — the field simply isn't tracked; changes go undetected with no error.
- **A non-nullable property** (`public int Grade { get; set; }`) — breaks the engine; it must be `int?`.
- **Confusing the identifier attributes with `[DuplicationKey]`** — identifiers persist the mapping; `[DuplicationKey]` finds a twin when there's no mapping yet.

## You've got this when you can…
- Write an entity class with `[EntityType]`, an identifier attribute, `[EntityProperty]` fields, and a `[DuplicationKey]`.
- State that every property must be nullable, and say why.
