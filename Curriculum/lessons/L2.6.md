# L2.6 — Add it to a Run

## In one line
The last step is **declarative**: add your entity to a Run's **`Segments`** in `appsettings.json` — a **Migration** to push it in and a **GarbageCollection** to clean it up — in the **right order**.

## The idea
Your POCO, feed, and sink are code; the **Run** that uses them is config (L1.7). From `appsettings.json`:

```jsonc
"Runs": [
  {
    "Name": "PsStdntToDdh",
    "SourceSystem": "Power School",
    "Segments": [
      { "Type": "Migration",         "EntityType": "School" },
      { "Type": "Migration",         "EntityType": "Student" },        // references School
      { "Type": "Migration",         "EntityType": "StudentAddress" }, // references Student  <-- your new entity
      { "Type": "GarbageCollection", "EntityType": "StudentAddress" },
      { "Type": "GarbageCollection", "EntityType": "Student" },
      { "Type": "GarbageCollection", "EntityType": "School" }
    ]
  }
]
```

To add a new entity (say `StudentAddress`):
1. Add a **`Migration`** segment **after its parents** (an address references a student, so it migrates after `Student`).
2. Add a **`GarbageCollection`** segment **before its parents** (GC runs in reverse so you don't delete a `Student` while addresses still point at it).

It's the same dependency logic you'd use inserting into and deleting from foreign-keyed tables: **parents first in, children first out.**

## Why it matters
This is what actually makes the engine run your new connector. And ordering is a real, common failure mode — get it wrong and you get foreign-key violations (several entries in `ExceptionHistoryWithResolutions/` are exactly this).

## Watch out for
- **Listing GC in the same order as Migration** — GC must be the reverse; children before parents.
- **Migrating a child before its parent** — the parent record won't exist yet → reference error.
- **Forgetting the GarbageCollection segment** — records the source dropped will linger in the destination.

## You've got this when you can…
- Add a Migration and a GarbageCollection segment for a new entity in `appsettings.json`.
- Explain why you migrate parents before children but garbage-collect children before parents.
