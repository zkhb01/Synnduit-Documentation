# L1.9 — POCO & attributes

## In one line
A **POCO** is the plain C# class describing one entity type (`Staff`, `Student`, `School`), and its **attributes are the contract** that tells the engine how to treat each property.

## The idea
POCO = "Plain Old CLR Object" — just a class with properties, one per entity type. What makes it a *Synnduit* POCO is the attributes decorating the class and its properties. From `Staff.cs`:

```csharp
[EntityType("2853506F-8A34-4296-A71A-E175A0EC6EA6", typeof(SchoolObjectModel))]
public class Staff : Entity
{
    [SourceSystemIdentifier]                 // which property is the source-side ID
    public string Code { get; set; }

    [EntityProperty]
    [DuplicationKey]                         // dedupe on EmployeeId
    public string EmployeeId { get; set; }

    [EntityProperty] public string FirstName { get; set; }
    [EntityProperty] public string LastName  { get; set; }
}
```

The attributes are the contract between your class and the engine:

| Attribute | Tells the engine… |
|---|---|
| `[EntityType(<guid>, <destinationSystem>)]` | this class is an entity type, globally identified by the GUID |
| `[SourceSystemIdentifier]` | which property holds the **source-side ID** (one end of the mapping) |
| `[DestinationSystemIdentifier]` | which property holds the **destination-side ID** (the other end) |
| `[EntityProperty]` | this field should be **tracked for change detection** |
| `[DuplicationKey]` | use this field to **match possible duplicates** during dedup |

A property with no `[EntityProperty]` isn't tracked; the identifier attributes are what make mappings (L1.6) possible; `[DuplicationKey]` is what makes dedup (L1.11) possible.

## Why it matters
The POCO + its attributes is the *one* place you declare everything the engine needs to know about an entity: its identity, which fields matter, how to recognize the same record on each side, and how to spot a duplicate. Reading a POCO's attributes tells you how a record will behave in a run.

## Watch out for
**Treating attributes as decoration.** They're not cosmetic — each one changes engine behavior. Forget `[EntityProperty]` on a field and its changes won't be detected. Forget `[SourceSystemIdentifier]` and the engine can't build a mapping. (There's also a subtle rule that tracked properties must be **nullable** — that's the L0.E2 gotcha; here, just know the attributes are functional, not labels.)

## You've got this when you can…
- Define a POCO as the C# class for one entity type.
- Match each attribute to its job (`[EntityType]`, `[SourceSystemIdentifier]`, `[DestinationSystemIdentifier]`, `[EntityProperty]`, `[DuplicationKey]`).
- Explain what `[EntityProperty]` does (marks a field for change detection) and what `[DuplicationKey]` is for (dedup matching).
