# L0.O1 — Interfaces & implementation

## Generic skill (curated — don't re-teach)
An interface is a **contract**: a list of members (methods, properties) with no bodies. A class that says `: IThing` promises to **supply every member** the interface declares — the compiler enforces it. If you can read `class Foo : IThing` and know Foo must implement all of `IThing`'s members, you're solid.
→ Refresher: **Microsoft Learn — interfaces** (`learn.microsoft.com/dotnet/csharp/fundamentals/types/interfaces`).

## The Synnduit slice
Synnduit's connectors are exactly this pattern. `IFeed<T>` and `ISink<T>` are the contracts; your classes fulfill them:

```csharp
public class StaffFeed : IFeed<Staff> { /* must implement IFeed<Staff> members, e.g. LoadEntities() */ }
public class StaffSink : ISink<Staff> { /* must implement ISink<Staff> members: New/Create/Get/Update/Delete */ }
```

Because `ISink<T>` is a contract, declaring `: ISink<Staff>` obligates you to provide **all** its members — that's why every sink has the same New/Create/Get/Update/Delete shape (L1.8). The engine only ever talks to your class *through* the interface, which is what lets it load and call any connector you write.

## Placement check
Does implementing `ISink<T>` mean you provide *all* its members, or can you pick a subset? (Answer: all.) Pass and you skip ahead.

## If this is shaky
Read the MS Learn interfaces page, then map `ISink<T>`'s member list onto a real sink's methods — each interface member = one method you must write.
