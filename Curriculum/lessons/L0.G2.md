# L0.G2 — Implementing a generic interface

## Generic skill (curated — don't re-teach)
This is L0.G1 (generics) and L0.O1 (interfaces) combined: implementing a *generic* interface. When you write `class Foo : IExample<Bar>`, you (1) bind the type parameter `T` to `Bar`, and (2) implement every member — with `T` now meaning `Bar` throughout the contract. So `IExample<T>`'s `void Add(T item)` becomes `void Add(Bar item)` in your class.
→ Refresher: **Microsoft Learn — generic interfaces** (`learn.microsoft.com/dotnet/standard/generics/interfaces`).

## The Synnduit slice
Every Synnduit connector you write is a generic-interface implementation where **`<T>` is your entity POCO**:

```csharp
public class StaffFeed : IFeed<Staff> { ... }                     // T = Staff
public class TeamSiteWebPartSink : ISink<TeamSiteWebPart> { ... }  // T = TeamSiteWebPart
```

Reading `ISink<TeamSiteWebPart>`: the interface is `ISink<T>`, the entity bound to `T` is `TeamSiteWebPart`, and you must provide all the members `ISink` declares (New/Create/Get/Update/Delete) — now typed to `TeamSiteWebPart`. That's the whole shape of writing a sink or a feed: *pick the interface, bind your entity as `<T>`, implement the contract.*

## Placement check
In `class TeamSiteWebPartSink : ISink<TeamSiteWebPart>`, what does `TeamSiteWebPart` bind to, and which members must you provide? (T; all of ISink's members, typed to TeamSiteWebPart.) Pass and you skip ahead.

Walk a real sink class: interface on the left (`ISink`), your entity as `<T>`, and the five methods as the contract you fill in. Then do the same with `StaffFeed : IFeed<Staff>`.
