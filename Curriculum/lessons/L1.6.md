# L1.6 — Mapping (the source ↔ destination link)

## In one line
A **mapping** is a stored row linking one source record's ID to the destination record it created — and it's the single reason re-running a sync **updates** instead of **duplicates**.

## The idea
When Synnduit creates a record in the destination, it doesn't just walk away. It writes a **mapping** into StarBridge: *"source ID `X` ↔ destination ID `Y`."* That little row is the engine's memory of "I already made this one."

Walk two runs:

- **Run 1.** Source has Staff `Code=12345`. No mapping exists yet → the engine **creates** the destination record (say destination ID `abc-guid`) and writes a mapping: `12345 ↔ abc-guid`.
- **Run 2.** Source still has Staff `12345`. The engine **looks up the mapping**, finds `12345 ↔ abc-guid`, and so it **updates** `abc-guid` (or detects no change) — it does **not** create a second record.

That lookup is what turns a blind copy into a sync. It depends on both prerequisites: the *delta* (L1.4) decides whether anything changed, and *StarBridge* (L1.5) is where the mapping row lives.

The POCO tells Synnduit which property is the source ID (`[SourceSystemIdentifier]`) and which is the destination ID (`[DestinationSystemIdentifier]`), so it knows what to store on each side of the mapping.

## Why it matters
Mapping is the mechanical answer to the very first promise in L1.1 — "the same record is updated next time, not duplicated." Almost every later behavior (no duplicates, change history per record, garbage collection of records whose source disappeared) is built on the mapping existing.

## Watch out for
**"It avoids duplicates by matching on the data each run."** Not for already-synced records — once a mapping exists, the engine matches by the *stored link*, not by re-comparing fields. (Field-based matching is what *deduplication* does, and only for records that have **no** mapping yet — that's L1.11.) Mapping = "I've seen this exact source record before, here's its destination twin."
