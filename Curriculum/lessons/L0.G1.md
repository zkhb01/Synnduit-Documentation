# L0.G1 — Using generic types

## Generic skill (curated — don't re-teach)
A generic type takes a *type parameter* in angle brackets: `List<Staff>` is "a list **of Staff**", `IEnumerable<int>` is "a sequence **of int**". The `<T>` just says what kind of thing is inside. If you can read `List<T>` / `IEnumerable<T>` / `Dictionary<K,V>` and say what the parameter means, you're solid here.
→ Refresher: **Microsoft Learn — C# generics** (`learn.microsoft.com/dotnet/csharp/fundamentals/types/generics`).

## The Synnduit slice
You don't *define* generic types in day-to-day Synnduit work — you *read* them. The one you'll meet immediately is the feed's return type:

```csharp
public IEntityCollection<Staff> LoadEntities() { ... }      // StaffFeed
public IEntityCollection<Guardian> LoadEntities() { ... }   // a Guardian feed
```

`IEntityCollection<Staff>` is simply "a Synnduit collection **of Staff** entities" — the snapshot a feed returns (L1.4/L1.8). The `<TEntity>` is always your POCO type. Same idea as `IEnumerable<Staff>`, just Synnduit's own collection interface.

## Placement check
Given `IEntityCollection<Staff>`, can you say it's a collection of `Staff` (not "of anything")? That's the bar — pass and you skip ahead.

## If this is shaky
Read the MS Learn generics page, then look at `StaffFeed.LoadEntities()` returning a collection of `Staff` — the `<Staff>` is what's *in* the collection.
