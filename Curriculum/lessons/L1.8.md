# L1.8 — iFeed & iSink (the two connectors)

## In one line
The two plug-ins from the engine model have names: a **feed** (`IFeed<TEntity>`) reads the source snapshot; a **sink** (`ISink<TEntity>`) writes the destination. You write both.

## The idea
Recall L1.3: you supply a source connector and a destination connector. Concretely:

- **iFeed — `IFeed<TEntity>`** — the **source** connector. Its job is to produce the snapshot. The core method is `LoadEntities()`, which returns a collection of POCOs. Tagged `[Feed(SourceSystem = typeof(...))]`.

  ```csharp
  [Feed(SourceSystem = typeof(HumanResources))]
  public class StaffFeed : IFeed<Staff>
  {
      public IEntityCollection<Staff> LoadEntities()
      {
          using var context = this.hradFactory.CreateHRAD();
          return context.CCS_HR_AD_SYNC
              .Where(Util.ActiveStaffWithManager)
              .Select(s => new Staff { EmployeeId = s.EMPLID, FirstName = s.FIRST_NAME, ... })
              .ToList();
      }
  }
  ```
  You query the source however you like and return the POCOs. (Note it returns *all* matching rows — the full snapshot from L1.4.)

- **iSink — `ISink<TEntity>`** — the **destination** connector. It knows how to act on the destination: **New / Create / Get / Update / Delete**. Tagged `[Sink(DestinationSystem = typeof(...))]`.

The `<TEntity>` in both is the POCO — `IFeed<Staff>`, `ISink<Staff>`. There's also an **iCacheFeed** (`ICacheFeed<TEntity>`) that re-reads the destination's current state for diffing; it's often combined with the sink in one class (`SinkAndCacheFeed.cs`).

The engine calls these for you. It calls your feed to get the snapshot, computes the delta, and then calls the matching methods on your sink to apply it.

## Why it matters
"Feed" and "sink" are the words you'll use to *describe where code goes*. New source? Write a feed. New destination? Write a sink. Knowing which interface owns which direction (and which CRUD methods live on the sink) tells you where any given piece of integration logic belongs.

## Watch out for
**Putting create/update/delete logic in the feed.** The feed only *reads* the source and returns POCOs — it never writes anything. All destination writes (New/Create/Get/Update/Delete) live on the **sink**. Feed = read source; sink = write destination.

## You've got this when you can…
- Match each interface to its direction: `IFeed<T>` reads the **source**; `ISink<T>` writes the **destination**.
- State that you (the developer) implement both.
- Say which side owns Create/Update/Delete (the **sink**) and what the feed's core method returns (a snapshot of POCOs).
