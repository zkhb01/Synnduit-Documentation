# L1.13 — Multi-source entities (several systems of record)

## In one line
One destination entity type can be maintained by **several source systems at once** — declared with `[SharedSourceSystemIdentifiers(...)]` — where each source is the **system of record for a *portion* of the data** (some records, and/or some columns), all **converging** on shared destination records instead of duplicating.

## The idea
So far a sync has had one source feeding one destination. But a destination entity like **`School`** is fed by **several** sources — at CSSD, HR, JSON, and three PowerSchool variants:

```csharp
[SharedSourceSystemIdentifiers(
    typeof(HumanResources.HumanResources),
    typeof(Json.Json),
    typeof(PowerSchool.PowerSchool),
    typeof(PowerSchool.PowerSchoolRegular),
    typeof(PowerSchool.PowerSchoolYearRound))]
public class School : Entity { ... }
```

`[SharedSourceSystemIdentifiers]` tells the engine that **more than one source can own records of this type**. The key consequences:

- **Each source gets its own mapping.** A `School` fed by PowerSchool has a PowerSchool→destination mapping (L1.6); the *same* `School` also seen from HR gets an HR→destination mapping. Two source IDs, **one** destination record.
- **Sources converge, they don't multiply.** When a second source brings in a record the destination already has, **deduplication (L1.11)** matches it (by `[DuplicationKey]`) and creates a mapping to the existing record — rather than making a duplicate. Shared identifiers are what make that safe across sources.

## Co-ownership spans both rows *and* columns
`[SharedSourceSystemIdentifiers]` isn't only about which source owns which *records* — sources can also each contribute different **columns** of the *same* record. Usually it's both at once:

- **By row** — each source is authoritative for a *portion of the set*. PowerSchool owns most `School` records; and where the primary has a gap, a **supplementary source of record** fills it — HR has no **Contract Staff**, so **JSON** is the SOR for those, HR for the rest, all landing in the one destination entity.
- **By column** — each source **augments the shared record with the attributes it owns**. The DDH `School` is enriched from several systems: **PowerSchool** supplies the government-issued school code, **JSON** supplies `SiteUrlSuffix` (the school-website suffix), and so on. Each source sets only *its* columns and leaves the rest `null`.

Column co-ownership works because of the nullable rule (L0.E2): a source's `null` on a column it doesn't own is treated as *"not part of this sync"* and left alone — so PowerSchool's feed doesn't wipe the JSON-owned `SiteUrlSuffix`, and vice-versa. When a source *does* own a column and needs its `null` to actually take effect, that's what `[ForceNullPropagation(typeof(<source>))]` is for.

So the division of labor is: **`[SharedSourceSystemIdentifiers]` lets the sources converge on one record; the nullable-ignore default + `[ForceNullPropagation]` (L0.E2) govern how their columns merge.**

## Why it matters
A new developer reading `School` (or `Staff`) will see a list of source systems and needs to know that's deliberate: several systems co-own the entity, each for its portion, converged into one destination record. Miss it and you'll either wonder why there are "duplicate" feeds, or — the classic bug (L3.5) — a record references a source that isn't in the list, so its ID can't be mapped.

## Watch out for
- **Thinking multiple sources means duplicate destination records** — they don't; mapping + dedup converge them onto one record.
- **A source that isn't in `[SharedSourceSystemIdentifiers]`** — the engine can't map that source's IDs for the entity, which surfaces as an "unable to resolve reference identifier" exception (L3.5). Fix: add the source to the list.
- **Thinking `[SharedSourceSystemIdentifiers]` is only about records** — it enables co-ownership *by row and by column*; several sources can each contribute different attributes to the same record. How those columns merge is governed by the nullable-ignore default and `[ForceNullPropagation]` (L0.E2) — not by this attribute.
