# L1.12 — Thresholds & resumability

## In one line
Two safety features: **abort thresholds** stop a run before a bad feed can wreck the destination, and **resumability** means a crash mid-run loses no data — the next run picks up where it left off.

## The idea
Delta detection trusts your snapshot. So what happens when the snapshot is *wrong*? Picture a feed that should return 65,000 students but, due to a bug, returns **0**. Without protection, the engine would conclude every student disappeared and garbage-collect the entire destination entity. Thresholds are the guardrails against exactly this.

**Abort thresholds** (configured in `appsettings.json` under `ExceptionHandling`):

```jsonc
"ExceptionHandling": {
  "SegmentAbortThreshold": 30,                       // abort a segment after 30 exceptions
  "RunAbortThreshold": 101,                           // abort the whole run after this many
  "OrphanMappingPercentageAbortThreshold": 0.05,     // abort if >5% of mappings would orphan
  "GarbageCollectionPercentageAbortThreshold": 0.05  // abort if >5% would be deleted
}
```

- **Exception thresholds** — abort a segment (or the whole run) once too many records throw exceptions.
- **Deletion / garbage-collection threshold** — if a segment would delete more than the configured percentage of the destination, **abort instead**. In the 0-students example, comparing 0 against 65,000 blows past the 5% line and the run stops. Setting the percentage to 100% allows full deletion; omitting it assumes 100%.
- **Orphan-mapping threshold** — similar guard for mappings whose destination record can't be found.

**Resumability** is the other half: if the server crashes mid-run, no data is lost. Because StarBridge records progress as the run goes, the next execution resumes from where it stopped rather than redoing or corrupting work.

## Why it matters
These features are why an automated, unattended sync is *safe* to schedule. A bad upstream extract is not a hypothetical — it's the failure these settings exist for. Thresholds turn "a bad feed silently wiped the destination" into "the run aborted and alerted," and resumability turns "the box rebooted during the run" into a non-event.

## Watch out for
**Assuming the engine will always "just sync what it's told."** It won't, by design — if a run would breach a threshold it **aborts** rather than proceed. That's not a malfunction; it's the safety net doing its job. (And remember: an omitted deletion percentage defaults to 100%, i.e. *no* deletion guard — so the protection is only there if it's configured.)
