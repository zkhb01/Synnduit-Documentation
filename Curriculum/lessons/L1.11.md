# L1.11 — Deduplication & merge

## In one line
When a source record has **no mapping yet**, the engine uses the `[DuplicationKey]` to check whether it's *already* in the destination — and if so, links and merges instead of creating a twin.

## The idea
Mapping (L1.6) answers "have I synced *this exact* source record before?" But what about a record that's new to *this* source yet already exists in the destination (perhaps put there by another source, or a one-time import)? Creating it again would make a duplicate. **Deduplication** is the safety net for that case.

The sequence, when inserting a record that has no mapping:

1. Read the source snapshot and find this is an **insert** (no existing mapping for it).
2. Use the property you marked `[DuplicationKey]` (e.g. `UserPrincipalName`, or `EmployeeId` on Staff) to **look for a matching record in the destination**.
3. **No match found** → genuinely new → create a new destination record (`NewEntityCreated`).
4. **Match found** → it's a duplicate → **create a mapping** to that existing record and merge:
   - source and destination fields already agree → `DuplicateDetectedNoChangesMerged`
   - they differ → record the delta and update → `DuplicateDetectedChangesMerged`
5. If the match is only *probable* (several candidates), it's **referred for manual deduplication** (`ReferredForManualDeduplication`) for a human to resolve.

So dedup is the bridge between L1.9 (the `[DuplicationKey]` attribute) and L1.6 (a mapping gets created as the result) — "no mapping yet, but the key finds the twin, and now there's a mapping."

When a stored key can't express "is this a duplicate?" (say the answer needs a live API lookup), the matching can be a fully custom **`[DuplicationRule]`** instead of a `[DuplicationKey]` — same outcomes, your own logic. That's a coding topic; see **L2.7**.

## Why it matters
Multiple sources can feed one destination entity (e.g. `Staff` via `[SharedSourceSystemIdentifiers]`). Without dedup, the second source would duplicate everyone the first source already created. Dedup is what lets several sources converge on the same destination records instead of multiplying them. (That multi-source, several-systems-of-record model is its own topic — see **L1.13**.)

## Watch out for
**Conflating dedup with mapping.** Mapping is a direct lookup for records you've *already* synced. Dedup only runs for records with **no mapping**, and it matches on *data* (the `[DuplicationKey]`), not on a stored link. The end product of a successful dedup is a *new mapping* — after which future runs use the fast mapping path, not dedup.

## You've got this when you can…
- Explain that `[DuplicationKey]` lets the engine match an unmapped 'new' source record to an existing destination record and merge instead of duplicating.
- Walk the insert path: no mapping → check duplication key → create vs. merge (vs. refer for manual dedup).
- Distinguish dedup (data match, only when no mapping) from mapping (stored-link lookup).
